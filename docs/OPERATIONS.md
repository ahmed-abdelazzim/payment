# تشغيل Sarraf Ops والـ Outbox

## قبل النشر

- لا يبدأ التطبيق في وضع `production` إذا لم يحدد `DATABASE_FILE` صراحة. يمنع ذلك إنشاء قاعدة `./data/sarraf_ops.db` مؤقتة داخل حاوية الاستضافة من دون قصد.
- مسار SQLite الصريح يصلح فقط كجسر مؤقت لخدمة واحدة مع قرص دائم ونسخ احتياطية تم اختبار استعادتها. لا يشكل بديلًا عن PostgreSQL المُدار عند وجود أكثر من نسخة من الخدمة أو Worker مستقل.
- لا تحفظ قاعدة بيانات أو ملف WAL أو `.env` أو مفتاح جهاز في Git. أمر `npm run check:repo-safety` جزء من CI ويوقف الدمج عند اكتشاف ذلك.
- استخدم `GET /health` لفحص أن العملية تعمل و`GET /ready` لفحص اتصال قاعدة البيانات وإعدادات التشغيل. كلاهما لا يعيد أسرارًا أو بيانات عملاء.

## تشغيل الـ Outbox

تنشأ وظائف Outbox داخل نفس معاملة الأحداث المالية، لكنها لا تعني أن الرسالة أو الـ webhook وصل فعليًا. الحالة النهائية في `outbox_jobs` هي مصدر الحقيقة:

- `queued`: تنتظر التنفيذ أو إعادة المحاولة.
- `processing`: عامل العمل استأجرها لفترة محدودة.
- `completed`: أنهى العامل الإرسال أو لم يجد Endpoint مشتركًا لهذا الحدث.
- `failed`: وصلت إلى Dead Letter وتحتاج تدخل المشغل.

لا يبدأ الإرسال إلا بعد تعيين المتغيرين التاليين معًا إلى `true`:

```text
OUTBOX_WORKER_ENABLED=true
OUTBOX_DELIVERY_ENABLED=true
```

في بيئة الإنتاج شغّل عاملًا منفصلًا:

```text
npm run worker:outbox
```

لا تشغّل `OUTBOX_WORKER_EMBEDDED=true` في تطبيق الويب وفي العامل المنفصل في الوقت نفسه. يمكن استعماله مؤقتًا في نسخة واحدة من التطبيق، لكنه ليس بديلًا عن Worker مستقل وقاعدة بيانات مشتركة دائمة.

إعدادات التشغيل المتاحة:

```text
OUTBOX_POLL_INTERVAL_MS=10000
OUTBOX_BATCH_SIZE=10
OUTBOX_MAX_ATTEMPTS=8
OUTBOX_LEASE_MS=90000
OUTBOX_DELIVERY_TIMEOUT_MS=10000
OUTBOX_ALLOW_INSECURE_HTTP=false
LIMIT_ALERT_WARNING_PERCENT=80
LIMIT_ALERT_CRITICAL_PERCENT=90
```

تزيد مدة إعادة المحاولة تدريجيًا حتى 15 دقيقة. عند توقف عامل العمل بعد حجز وظيفة، يستعيد عامل آخر الوظيفة بعد انتهاء الـ lease. تحمل كل Webhook قيمة `Idempotency-Key` ومعرف الحدث نفسه، لذلك يجب أن يخزن المستلم المعرف ويعالج الحدث مرة واحدة. يجب أن تكون عتبة التحذير والعتبة الحرجة بين 1 و99، وأن تكون عتبة التحذير أقل من الحرجة.

## حماية الإرسال الخارجي

- Webhook URLs تقبل HTTPS فقط في الإنتاج.
- العامل يرفض عناوين localhost والشبكات الخاصة وعناوين metadata ويثبت نتيجة DNS قبل الاتصال.
- لا يتبع التحويلات Redirects.
- يوقع كل Webhook عبر `X-Sarraf-Signature` على شكل `t=<unix>,v1=<hmac>`، مع `X-Sarraf-Event` و`X-Sarraf-Event-Id`.
- لا تسجل سجلات العامل نص الرسالة أو Token تيليجرام أو Secret الـ Webhook أو Response body.

## معالجة وظائف فاشلة

راجع `outbox_jobs` حيث `status = 'failed'` وسجل التدقيق `OUTBOX_JOB_DEAD_LETTERED`. بعد تصحيح إعداد Telegram أو Endpoint العميل، أنشئ وظيفة جديدة أو أعد جدولة الوظيفة بعد مراجعة سبب الفشل. لا تغير حالة التحويل المالي لمجرد فشل إشعار خارجي.

## ما يحتاج تحققًا خارجيًا

هذا الكود لا يؤكد أن Telegram أو SMTP أو Endpoint العميل يعمل قبل وضع المفاتيح الصحيحة في مدير أسرار وتشغيل اختبار تسليم. لا تعتبر الإضافة إلى `outbox_jobs` أو ظهورها في `completed` دليلاً كافيًا على استلام العميل؛ راجع `webhook_deliveries` وحالة المستلم الفعلية.
